# Fifteen

**The most expensive fifteen minutes in a factory.** An open instrument for finding, valuing, and
operating 250 kW / 522 kWh behind-the-meter batteries at Massachusetts commercial and industrial sites.
It uses real load data, the real 2026 tariffs, and an audit trail for every number.

Built by [Aditya Swaroop](https://github.com/as567-code) for Powertown's Machine Learning Engineer
(intern) application. Independent project; not affiliated with Powertown. The battery parameters
follow the Powerblock spec sheet published at powertownusa.com.

**Live page:** https://as567-code.github.io/fifteen/ (static; runs entirely in the browser)
**Two-page summary:** https://as567-code.github.io/fifteen/memo.pdf

Every result and claim on the page is generated by the scripts below. Nothing is typed in by hand.

---

## What it does

| Question | Instrument | Data |
|---|---|---|
| What is one battery worth at *this* site? | Exact perfect-foresight dispatch + tariff-exact bills, Python and an in-browser port | Your Green Button CSV, or any of the featured sites |
| Which sites are worth a visit? | Valuation of 958 sites under National Grid G-3 and Eversource G-2 (Greater Boston); bill-only kNN screener; ConnectedSolutions value stacking (LP) | NREL ComStock 2025 R3 Massachusetts buildings, UCI and KIT metered C&I loads, ISO-NE 2018 |
| How much of that value survives not knowing the future? | Day-ahead quantile forecaster + receding-horizon controller with a sunk-peak rule, versus tuned baselines | 154 real metered customers: train 2012, tune 2013, test 2014 |

## Reproduce

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
scripts/00_download.sh                                # every public dataset, exact URLs inside
.venv/bin/python -I scripts/01_prepare_data.py        # build the 15-min load library
.venv/bin/python -I scripts/02_value_sites.py         # value every site under both tariffs (~30 s)
.venv/bin/python -I -u scripts/03_operate_backtest.py # forecaster + controllers, 2012/2013/2014 protocol (~30 min)
.venv/bin/python -I scripts/04_stack_connected_solutions.py  # LP value stacking (~10 min)
.venv/bin/python -I scripts/05_export_site.py         # write site/data/*
.venv/bin/python -m pytest -q                         # audits
cd site && python3 -m http.server                     # open http://localhost:8000
```

## Layout

```
fifteen/            the engine
  battery.py          Powerblock parameters (published spec + two stated assumptions)
  shave.py            greedy dispatch + bisection: exact perfect-foresight demand minimisation (numba)
  audit.py            independent LP (HiGHS) and physics invariants
  tariff.py           tariff JSON -> billing-demand weights -> monthly bills
  forecast.py         scale-free day-ahead quantile forecaster, look-ahead test
  control.py          non-anticipative controllers: forecast MPC, ratchet, timer
  stack.py            LP co-optimising demand charges with ConnectedSolutions events
scripts/            the pipeline, numbered
site/               static page; engine.js is a tested port of shave.py + control.py
tests/              LP agreement, physics, JS/Python parity, tariff-vs-source-PDF checks
data/tariffs/       official tariff PDFs (SHA-256 pinned) and the research notes behind tariffs.json
```

## Audits (all in `tests/`)

- **Optimizer vs LP.** The greedy/bisection oracle matches an independent HiGHS linear program on single-window, two-window and off-peak-discount billing rules.
- **Physics.** Every dispatch is checked for power limits, state-of-charge bounds, per-interval energy conservation with losses, and no export.
- **Browser parity.** `site/engine.js` reproduces the Python plans, controller traces (1e-6 kW) and bills (to the cent).
- **No look-ahead.** Scrambling the future must not change today's forecast features.
- **Agent output vs source.** An AI research agent gathered the tariffs. A test re-reads the hash-pinned PDFs and requires every modeled number and rule to appear verbatim.
- **Data repairs** found along the way (UCI daylight-saving artefacts, ComStock standard-time timestamps, a duplicated KIT meter) are documented in `scripts/01_prepare_data.py` and on the page.

## Assumptions worth arguing with

- 90% usable depth of discharge (470 kWh) and 90.3% AC round-trip efficiency. Powertown publishes neither.
- Metered load shapes from Portugal and Germany are billed on Massachusetts tariffs. They stand in for member Green Button data.
- Holidays stay inside peak windows; kVA billing and power factor are ignored; supply is a flat 14.3¢/kWh.
- ConnectedSolutions 2018 events are reconstructed from ISO-NE load (42 highest summer days, 2- and 3-hour mix matching Eversource's 2025 calendar).
